# NPCs and dialogue

- `game/npc/` owns ordinary villager schedules, movement and greetings. Generate `npc_catalogue.json` offline with `tools/import_npc_schedules.py` from the source cue table, native area routes and packed ANI catalogue. Use the source map/place pairs, weekday/season schedule variants and one shared villager scene. Story-dependent actors and cue actions are deferred. Anchor the 0.2 m grid at the visible soil edge (-4.4,-1.6) so one soil cell is exactly 2x2. Native AStar2D uses Manhattan distance and four-connected unit-cost edges; build in physics batches using layer 8 support, layer 1 capsule checks and the shared shadow footprint. Check mid-edge support and thin walls and replan after new obstacles. World owns area and clock integration. Run `tools/verify_npc_navigation.gd` and `tools/verify_npc_roster.gd` for route, collision and cast regressions.
- The schedule supplies one presence lookup per actor. Loaded actors report live area-local positions; unloaded actors report their selected schedule area and first route point. Dialogue receives nearby visible people and same-floor indoor awareness separately from the stricter conversation and witness radius. Use colloquial proximity for ordinary speech. When someone asks where a nearby visible villager is, let that person answer directly if their identity is clear from the current conversation. Supply a measured ground-plane straight-line distance in metres only for an explicit distance question. The supermarket can report co-presence without an exact position when a display blocks sight.
- Enter explicitly opens the text field. Sending hides it and uses the nearest visible NPC when no conversation is active. NPCs can speak without opening the text field. Z can also start live nearby dialogue (choose 交谈 for merchants). Escape ends; walking away closes the conversation. Speech bubbles follow both player and NPC, and NPC bubbles are clamped inside the camera viewport. NPC text reveals one character per 0.09 seconds, with a short pause at commas. Each complete sentence stays visible for a reading hold based on its length before the next one replaces it. The final sentence uses the same hold before fading. A closing question gets a longer reply window. Without a reply, the speaker gives a local farewell and returns to their schedule. Player messages can queue while a response streams, and the world keeps running. Open speech sends the live nearby listeners and shared context to Pi. A named speaker goes first, and another relevant listener may join on any turn. Explicit group invitations get at least two replies when two people are present and allow up to three. Each NPC finishes their reading hold and fade before the next NPC starts speaking. Private speech stays with its intended recipient. Group replies can only retrieve prior speech known to their whole audience. Entering a villager's sight within 2 m marks a local arrival, turns idle villagers toward the player, and adds recent arrival context to dialogue without requesting a model response. If the player stops near an idle villager, the villager may initiate a conversation without focusing the text entry. Proactive starts have a shared 20-second cooldown and a once-per-villager daily limit. The history records a player message at send time and an NPC reply on completion.
- NPCs move one adjacent grid cell at a time, on one world axis per step. Prefer straight and single-turn routes through the four-connected graph when available. Otherwise use Manhattan A* to find the minimum step count, then minimize heading changes across routes of that length. On contact, refresh nearby cells and replan from the actual body position on the same physics tick. Start a batched rebuild immediately if the local update cannot find a route. Retry after a short pause only when the rebuild finds no route. Keep the chosen endpoint until arrival or a schedule change.
- The desktop Pi Agent worker is launched on first dialogue. Set up Node.js 22.19+ and run `npm ci --prefix game/npc/dialogue/pi --ignore-scripts` from the project directory. The game tries a valid absolute executable path in `user://pi-node.path`, a portable runtime in `pi/runtime/`, the standard Windows installation folders, then PATH. For a packaged game, put the `pi` folder with the worker, installed dependencies and portable Node beside the game executable. F1 reports the last dialogue error if the worker cannot start. It uses `DEEPSEEK_API_KEY` or the existing `user://deepseek.key` and passes it through stdin only. Pi runs DeepSeek Flash without tools, using current local perception and witnessed history. F1 shows per-run provider-reported input, cache hits and output, plus counts of submitted and reported requests. Closing midstream can leave usage unreported. Schedules are local. Active dialogue and an eligible proactive greeting can issue model requests.
- Schedule changes walk loaded villagers to the real exit. During play, an arriving villager comes through an authored entrance. Dialogue can propose a temporary trip to a connected public destination named by the player. Pi sends a structured destination separately from its streamed speech. Godot validates the destination and opening hours, uses the same Manhattan path and checks the door again at departure. Unloaded route legs consume estimated travel time and use their authored entries. A temporary visit lasts 48 simulation seconds before the original schedule resumes. The F1 map exposes the live or estimated travel position. Run `tools/verify_npc_travel.gd` for physical step and entrance checks.
