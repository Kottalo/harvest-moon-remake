# Camera and scenery

- The user rejected and removed the entire 2026-11-03 outdoor visual-continuation experiment after a performance regression (live farm snapshot about 47 FPS, p95 ~29.7 ms on UHD 620). Do not restore its camera-child quad, shader, RGBAF fields, materials, build tools or runtime references, or introduce a new baked background as a substitute. All that experiment's project files are deleted; previous Git history retains the evidence. The latest authorised solution is native maps plus strict camera limits and a modest closer orthographic view. Frame-rate improvement is not measured yet: the user stopped the game before a live A/B test; do not claim stable 60 FPS without a new real measurement.
- Outdoor camera limits belong to world_camera.gd. World supplies the loaded native scene and original zone-header flags; flags & 0x1800 disables limits indoors/mines. Cache the projected native-map envelope at load, erode by the orthographic viewport footprint with .05 world-unit padding, and strictly clamp the focus; never relax limits to recenter an edge-positioned player. Use the original 1.0 base calibration, orthographic size sqrt(9^2+4.5^2)*.24. If a very narrow map/very wide viewport leaves no valid centre, the user permits tightening the view further: shrink size by 5% per projection-fit attempt, only on map/viewport/zoom changes. Restore the requested base zoom on map/viewport changes. Preserve angle, physical player/world proportions, contact stabilization, interpolation, coast's shared bounds and overview restore. No extra render pass/texture/shader or terrain extension. verify_camera_limits.gd checks all 43 areas, four aspect ratios and strict corners even for border/outside player poses; synthetic narrow maps fit closer instead of exposing the border. The envelope remains a conservative geometric test rather than GPU pixel acceptance; concave/alpha edge cases need actual scene review, not a background workaround.
- Farm gameplay always uses the measured inset outline in world_camera.gd with the shared .05 padding and original zoom. Its short sides cut the concave river and bank tips. This replaces the F1 farm trial and the farm mesh hull. Other maps retain their own camera limits.
- Contact camera stabilization: world_camera.follow keeps ordinary physics interpolation, but when grounded with resolved velocity near zero it holds a render focus within 4x the body's safe_margin. Collision recovery is not intentional camera motion. Direct updates/movement/large displacement reset that anchor. Ease the clamped render focus with a frame-rate-independent 35 ms response and settle exactly once within .00005 world units. Direct updates and projection changes bypass smoothing so map/respawn/overview cuts stay immediate and the viewport never eases from an invalid centre. Calculate the fixed gameplay basis from -eye_offset rather than recomputing look_at from world-space subtraction each frame. verify_blocked_camera.gd exercises real blocked seams, constant scenery projection, immediate reverse movement and direct/teleport updates at 60/120 Hz; never change collision sizes or snap actual movement to pixels to hide jitter.
- Player sprites have fixed world dimensions calibrated at the original camera distance. Never compensate their size for camera distance, FOV or overview zoom; player and scenery must scale together.
- `game/camera/`: camera projection and follow/overview behavior only. On 2026-10-29 the user explicitly replaced perspective with ORTHOGRAPHIC gameplay. Keep the existing yaw/elevation and centre-plane framing: orthographic size sqrt(9^2+4.5^2)*240/1000, KEEP_HEIGHT. reset_gameplay restores this orthographic projection after overview. Player/world dimensions stay fixed; equal world lengths must project equally at different depths. The old 1.44 distance scale now calibrates framing, not perspective.
- Physics interpolation is enabled; the camera itself does not interpolate twice and follows `get_global_transform_interpolated()` during rendering. Direct camera checks use the physics transform. Reset the player's interpolation after any map/respawn teleport; retain native physics and the requested original 1.0x camera calibration.
