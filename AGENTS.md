# Project instructions

## Directory contract

- `game/player/`: player scene, input, movement, ANI playback and shared player assets only. No world/map loading dependencies.
- Player sprites have fixed world dimensions calibrated at the original camera distance. Never compensate their size for camera distance, FOV or overview zoom; player and scenery must scale together.
- Anchor the player sprite at the body's XZ contact point with one fixed canvas pivot (`Sprite3D.offset`). ANI frame/part dx/dy are already baked into the atlas; never change the pivot using each frame's alpha bounds (`foot_y` is diagnostic metadata only). Preserve the original gait/pose offsets across all frames and facings. While grounded, align the pivot with nearby upward-facing render geometry (query-only layer 4), falling back to capsule support-plane clearance. This adjusts only sprite Y: continuous ramp collision and native body motion stay authoritative. Never reuse the original hand-projection offset as a 3D foot position. Run `tools/verify_player_grounding.gd` for changes to this alignment.
- `game/camera/`: camera projection and follow/overview behavior only. Preserve the original yaw/FOV; the user requested two successive 20% distance increases on 2026-10-28 (distance scale 1.44).
- `game/world/`: world entry scene, location catalog, navigation/exits and simple navigation prompts. Do not put player animation, camera math, shops, crops or NPC behavior here.
- `game/rendering/`: shared source-model and player drawing shaders. Preserve source backface culling and per-primitive average depth (including 0x8000/0x4000 depth biases). The whole player uses its ground-relative source hand point for depth, independent of pose pixels; never disable depth testing to force the player over every object. Keep neutral additive-black primitives for collision but exclude their no-op drawing. Run the actual GPU front/behind check through `tools/verify_render_order.gd` with Godot AI, plus native checks after rebaking.
- `game/locations/<semantic_name>/`: one original place per folder, its native scene and texture atlases. Use names such as `farmhouse`, `library`, `clinic`; raw source area numbers belong in metadata, never the primary directory name.
- `tools/`: offline conversion and runnable checks. `tools/generated/` contains ignored, regenerable conversion intermediates, not runtime code.
- `reference/` is read-only source reference; `addons/` is third-party code; `verification/` is evidence, not gameplay.
- The old `scenes/farm.tscn`, `scenes/original_farm.scn`, `scripts/farm.gd` and farm texture aliases are retained for the user's existing editor tabs. The old script only redirects to `game/world/world.tscn`. Add no new logic to these compatibility paths. Do not rename/close the user's open scene tabs as part of cleanup.
- Use snake_case filenames/folders and PascalCase Godot nodes. Place assets beside the location/player that owns them; do not create generic `misc`, `utils` or `manager` dumps.
- After moving/adding runtime files run `python tools/check_structure.py` as well as the relevant runtime checks. Update this contract when a real new subsystem is added.
- Keep the editor open while working. Use godot-ai MCP asset scans for new files; do not launch a second headless editor against the same project's editor layout while the user is using it.

- This is a native Godot remake in progress, not the existing PS1 recomp build. Keep the sibling `Source` and `Game` projects intact unless the user requests changes there.
- Use the user's `coalslav/hmbtn-decomp` checkout in `reference/hmbtn-decomp` as the primary behavioral/format reference. Read PORTING.md for the verified formats and current scope. Do not claim the whole game is ported.
- Use godot-ai MCP for live editor state, project runs, input, screenshots and error inspection. Select the session whose project path is this directory. Plugin/server are both 4.3.1. Authentication uses `godot-ai attach` over stdio; do not replace it with an unauthenticated HTTP URL. Limit screenshots to longest edge 800 to stay under the transport event budget.
- Runtime assets are native `.scn`, PNG and JSON. Disc reads belong only in the offline importer. Never add a ROM reader, PS1 interpreter or recomp dependency to the Godot runtime.
- Preserve the corrected coordinate transform `(x,-y,-z)/1000`. Up/Down/Left/Right must project NE/SW/NW/SE with exactly four directions. Default camera uses the original H=1000 on 320x240 perspective (vertical FOV ~13.68555 degrees); orthographic overview is only a debug view. Do not reintroduce screen-axis movement or an estimated camera zoom. Bake all visible FarmZoneModel records at their source positions.
- Godot 4.7.2 portable executables are at `../Tools/Godot`; use the compatibility renderer on this machine.
- For runtime/physics changes, run `--headless --path . --script tools/verify_runtime.gd`. For importer changes, run its `--check`, re-extract, bake and run the native check using Import-Assets.ps1. Do not repeat conversion when only runtime code changed.
- Player collision changes must also pass `tools/verify_collision.gd` at 60 Hz and with `-- --120hz`: original ground/ramp paths including seams and edges, real stairs, tall/thin obstacles and low overhead clearance. `tools/verify_stair_transitions.gd` must exercise the full room transition via physical keys, not just reaching a visual tread height.
- Preserve source ground flags from `ground.c` / `farm_probe.c`: physical ground uses mask 0xC080 (layer 2); forward walkability uses 0xE080 (layer 8). Solid positioned objects use layer 1; player mask is 3. The complete render mesh is query-only layer 4 (`VisualGeometryReference`), never a substitute for source collision geometry: decorative stair risers can overlap the real invisible ramp.
- `player.c` uses 200-unit ground tolerance and a 48-unit forward probe. Adapt the probe to the native capsule radius and tolerate one source unit at floating triangle seams. Preserve the distinction between `ZONE_FLAG_FACING` (0x1000) and `ZONE_FLAG_HAS_EVENT` (0x200): facing/event combinations decide action gating; 0x1000 alone does not mean every stair requires E.
- Never globally suppress exits after a scene change. Original automatic arrival coordinates are outside return zones; consume a held interaction button only. Stair tests must reverse physical input immediately on arrival without waiting, teleporting, or resetting transition state: a 0.6-second cooldown previously let players walk past the downstairs trigger.
- The user now wants all traversable stairs represented by continuous ramp collisions. Do not restore per-step lifting or manual player Y teleports. Player height comes from native `move_and_slide` plus floor snap. Each location's `walkable_ramps.json` defines named ramps/landings baked into `WalkableRamps` (layer 10); remove conflicting floor triangles only within their footprint while preserving surrounding platforms. Preserve visible stairs. The ground ray in the player only prevents walking into unsupported/forbidden areas.
- Include road joints/bridges in ramp audits, not just visibly repeated treads. The town-south upper-road joint at (1.205002, 0.800812, 5.26998) had a source normal (0, 0.6, -0.8), i.e. 53.13 degrees, which a 45-degree floor limit incorrectly rejected. The player now accepts walkable grades up to 60 degrees; that road is also smoothed to a 29.745-degree continuous ramp. Keep vertical obstacle/ceiling checks.
- The user authorized a private GitHub checkpoint with project assets stored in Git LFS. Keep it private; never upload the disc/ROM or make game assets public.
- The user requests every completed update be committed and pushed after verification. Check that local LFS assets are hydrated; a clean Git status alone is insufficient.
