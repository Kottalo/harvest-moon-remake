# Project instructions

## Directory contract

- `game/player/`: player scene, input, movement, ANI playback and shared player assets only. No world/map loading dependencies.
- `player_actions.gd` owns the source ANI action state, charge/release timing and held-item drawing; it emits interaction/tool signals. `actions/action_catalog.json` and its named atlases are extracted offline. Full actions use a 256-pixel common canvas packed with AtlasTexture margins; its origin (128,176) preserves the exact existing (0,53) pivot and pixel_size. Do not trim away the original pose offsets or clip long tool/water effects. `tools/import_player_actions.py --check` compares the original 90 frames pixel-for-pixel after unpacking.
- `game/items/` owns native loose-item pictures and session records. Farm debris is taken from the title's new-game field layout, not invented positions. Pickups, placement/discard and tool hits update those records; do not claim crop growth or animal gameplay from animation playback alone.
- Static loose items use three cropped MultiMesh batches with the original canvas coordinates/UVs and contact depth. Preserve individual stone/branch colliders, batch slot updates and field records. GPU comparison against original Sprite3D drawing must preserve the bounds and pixels.
- `set_area` rebuilds loose items only on a real location load. Pickup/placement must preserve unrelated nodes, colliders, batches and flights. Each batch reserves one slot per field cell on entry and draws only its dense live prefix; remove by moving the last instance into the hole, add to the end. Static batches disable physics interpolation so slot reuse never draws movement from a former occupant's position. Never resize the GPU buffer or call `set_area(current_area)` to place an item. `tools/verify_actions.gd` checks identity/capacity across repeated placement, empty-type restoration and an unrelated flight; its isolated GPU run also reads actual instance transforms (the headless dummy renderer returns identity).
- PS1 `addPrim` prepends to the ordering list: an item submitted BEFORE the body is displayed in FRONT of it. Carry poses keep the item in front for all four directions. Pickup/release are in front for down/right, behind for left/up. Validate all 12 combinations through the actual player action layer parameters in `tools/verify_actions_gpu.gd`; do not invert this order again.
- Player sprites have fixed world dimensions calibrated at the original camera distance. Never compensate their size for camera distance, FOV or overview zoom; player and scenery must scale together.
- Anchor the player sprite at the body's XZ contact point with one fixed canvas pivot (`Sprite3D.offset`). ANI frame/part dx/dy are already baked into the atlas; never change the pivot using each frame's alpha bounds (`foot_y` is diagnostic metadata only). Preserve the original gait/pose offsets across all frames and facings. While grounded, align the pivot with nearby upward-facing render geometry (query-only layer 4), falling back to capsule support-plane clearance. This adjusts only sprite Y: continuous ramp collision and native body motion stay authoritative. Never reuse the original hand-projection offset as a 3D foot position. Run `tools/verify_player_grounding.gd` for changes to this alignment.
- `game/camera/`: camera projection and follow/overview behavior only. Preserve the original yaw/FOV; the user requested two successive 20% distance increases on 2026-10-28 (distance scale 1.44).
- Physics interpolation is enabled; the camera itself does not interpolate twice and follows `get_global_transform_interpolated()` during rendering. Direct camera checks use the physics transform. Reset the player's interpolation after any map/respawn teleport; retain native physics and the 1.44x distance.
- `game/world/`: world entry scene, location catalog, navigation/exits and simple navigation prompts. Do not put player animation, camera math, shops, crops or NPC behavior here.
- `location_loader.gd` uses native threaded requests to warm only the current location and direct neighbours (both coast regions count together). Release obsolete cached scenes, consume finished requests and leave headless checks deterministic. HUD refreshes are limited to 10 Hz and a single Windows CJK-capable font avoids per-script fallback draw switches.
- `game/time/` owns clock/calendar, source subtractive tint and bed menu. `day_cycle_catalog.json` comes from the source place table and zone headers through `tools/import_day_cycle.py`; runtime never reads the disc. Source one_minute=30 with clockFrames>=15 at 30 Hz means 0.5 real seconds/minute. Source marked places, overview, menus and active fades pause time. Dates roll at 06:00, not midnight; 30 days/season, four seasons/year. Sleep and natural 06:00 rollover both return to the verified farmhouse morning coordinates; avoid advancing the date twice. This stage does not implement fatigue/crops/animals/seasonal art/save files. Run `tools/verify_day_cycle.gd` plus the isolated `tools/render_day_cycle_check.gd` GPU entry.
- Source door hinges live in `source_doors.gd`: 8 turn-units acceleration, 0x420 opening limit, 11-tick hold, 30 Hz updates and mirrored twins. Only catalogue exits with a verified source door model rotate a panel. Transitions use `location_transition.gd`: freeze and subtract the old image by floor(255/21)=12 at 30 Hz, then load under black and fade the new scene in at the display's 60 Hz rate. Lock input only during the active transition and keep held-key immediate returns; the coast stays seamless.
- `game/rendering/`: shared source-model and player drawing shaders. Preserve source backface culling, but use normal continuous 3D depth for solid scenery: writing one average depth per face caused stair/terrain distortion. Only the whole player uses its ground-relative source hand point for depth, independent of pose pixels. Keep depth testing enabled. Preserve PS1 STP classification and blend mode separately from opaque texels; transparent effects do not write depth. Neutral additive-black primitives keep collision but have no drawing. Run GPU checks in `tools/verify_render_order.gd` through Godot AI plus native checks after rebaking. The user requested Linear filtering and 4x MSAA.
- Water/mist/other scene texture animation comes from `FarmModeScript.frames` and `scene_view.c` VRAM copies: preserve 30 Hz keyframe durations, odd-height reset, and PLACE_2C's three repeated strips. Decode motion atlases offline and bake them as native ImageTextures; no runtime disc reads. The user approved smooth water: interpolate the source 2-row scrolling keyframes, crossfade wave frames and add subtle world-space UV ripples on water maps. `source_animation.gdshaderinc` never moves geometry. `tools/verify_water.gd` checks actual GPU interpolation, changes and cycle resets. The game renders at a 60 FPS target with 60 Hz physics; source movement speeds and animation durations do not double.
- The user cancelled outdoor-map extension. Do not add backdrop terrain or replace source map boundaries to conceal the clear background. Keep the authorised town-square/beach connection.
- The summit's existing star/cloud and distant-mountain background meshes are enlarged in the original camera plane to cover their exposed edges. This is a background-only exception: keep view depth and horizon anchors, physical terrain and collision unchanged. Do not restore the cancelled terrain extension.
- Town square and beach share `game/world/coast.tscn` in continuous world coordinates. Beach is translated by (12.4,0,0.8); the shared upper landing is world x=5. The offline coast builder clips duplicate previews into each location's `coast_segment.scn`, retaining one complete beach staircase. Crossing changes the region label without reloading scenes, meshes, player coordinates or camera. Other areas retain source exits. Coordinate-aware checks use `area_to_world` / `world_to_area`; `tools/verify_coast.gd` must pass three lanes, walk/run, immediate return, stable mesh IDs and continuous floor/camera at 60/120 Hz.
- `game/locations/<semantic_name>/`: one original place per folder, its native scene and texture atlases. Use names such as `farmhouse`, `library`, `clinic`; raw source area numbers belong in metadata, never the primary directory name.
- `tools/`: offline conversion and runnable checks. `tools/generated/` contains ignored, regenerable conversion intermediates, not runtime code.
- `reference/` is read-only source reference; `addons/` is third-party code; `verification/` is evidence, not gameplay.
- The old `scenes/farm.tscn`, `scenes/original_farm.scn`, `scripts/farm.gd` and farm texture aliases are retained for the user's existing editor tabs. The old script only redirects to `game/world/world.tscn`. Add no new logic to these compatibility paths. Do not rename/close the user's open scene tabs as part of cleanup.

- After moving/adding runtime files run `python tools/check_structure.py` as well as the relevant runtime checks. Update this contract when a real new subsystem is added.
- Action checks are `tools/verify_actions.gd` and `tools/import_player_actions.py --check`. GPU action/alignment/transition checks run through `tools/run_render_check.py --log <absolute-path>`: its Godot process belongs to an isolated Windows desktop that is never switched to, so it cannot steal the user's focus.
